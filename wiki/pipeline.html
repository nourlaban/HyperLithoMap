Pipeline

Pipeline Workflow

The HyperLithoMap pipeline converts raw satellite sensor data into a fully classified geological map through a deterministic five-step sequence. Each step is idempotent — re-running the pipeline simply overwrites previous outputs without side effects.

◆ End-to-End Data Flow

Five-step pipeline from raw sensor file to classified geological map. Steps 1–4 are preprocessing; Step 5 runs four ML models in sequence.

◆ Step Details

1

Sensor Conversion → Stacked GeoTIFF

Raw Level-2 data from three sensors is normalised to a common float32 GeoTIFF format with a −9999 nodata value. Bad spectral bands (atmospheric absorption windows, sensor artefacts) are removed at this stage.

Code: preprocessing/converth5totiff.py — functions convert_h5_to_stacked_tiff(), convert_enmap_to_stacked_tiff(), convert_dat_to_stacked_tiff()
SensorRaw formatFunctionBands kept
PRISMA HDF5 .he5 (HDF5, SWIR + VNIR cubes) convert_h5_to_stacked_tiff() 234 (removes 5 VNIR edge + 76 SWIR water/thermal bands)
EnMap GeoTIFF .TIF (multi-band GeoTIFF) convert_enmap_to_stacked_tiff() 219 (removes 5 overlap bands 131–135)
PRISMA ENVI .dat + .hdr (ENVI BSQ) convert_dat_to_stacked_tiff() 234 (no bad-band list for Rabshi scene) 
# PRISMA bad-band lists in config.py
vnir_bands_to_remove = [1, 2, 3, 4, 5]                              # edge artefacts
swir_bands_to_remove = list(range(3,6))   +                         # VNIR-SWIR gap
                       list(range(40,57)) +                         # 1350–1450 nm H₂O
                       list(range(86,112))+                         # 1800–1950 nm H₂O
                       list(range(152,172))                         # 2450–2500 nm
Nodata convention: All conversions write nodata=−9999. Subsequent steps must mask these pixels before any arithmetic. The normalisation in hsmodel/utils.py :: load_HSI() excludes nodata from per-band min/max — including nodata in normalisation collapses all valid reflectance to ≈1.0 and destroys spectral variance.

Output

<intermediate_dir>/vnir_swir_stackedd.tif — float32 GeoTIFF, N bands × H × W, UTM coordinate reference system, nodata = −9999.

2

Rasterise Training Labels

Geological field-survey polygons (shapefile) are burned onto a raster grid co-registered pixel-for-pixel with the stacked GeoTIFF. The class integer values are read from the attribute column configured per-satellite in config.class_field.

Code: preprocessing/convertshapelabelstoraster.py  ·  called by src/pipeline.py :: _step_process_labels()

Output

<intermediate_dir>/colored_class_labels.tif — single-band integer raster. Background (unlabelled) pixels = 0. Class pixels = 1 … N.

3

Apply Colour Table

Assigns a human-interpretable RGB palette to the integer label raster for QGIS/ArcGIS inspection. This step does not alter any model inputs.

Code: preprocessing/color_map.py  ·  called by src/pipeline.py :: _step_apply_colormap()

The colour table is a plain-text .clr file with columns value R G B alpha label. Example from data/RabshimamabadataPrisma/input/plate.clr:

1  130  80  50  255  Hornfels
2   60 100 200  255  Limestone
3  200 160  60  255  Mudstone-siltstone
...
4

Stratified Train / Test Split

Randomly samples config.samples pixels per class from the label raster, then splits them into a training mask (1 − test_size) and a test mask (test_size) using stratified sampling to preserve class proportions.

Code: preprocessing/split_pixel.py  ·  called by src/pipeline.py :: _step_create_masks()
ParameterConfig keyDefaultEffect
Pixels per classconfig.samples1000Total labelled pool per class
Test fractionconfig.test_size0.7070 % held out for evaluation

Outputs

  • intermediate/train_mask.tif — binary raster, 1 = training pixel
  • intermediate/test_mask.tif — binary raster, 1 = test pixel
Spatial autocorrelation: Purely random pixel sampling does not enforce spatial separation. Pixels from the same polygon can appear in both train and test sets. For rigorous validation, replace the polygon-level split in split_pixel.py with a block-holdout scheme.
5

Train Models & Generate Prediction Maps

All four models share the same training/test masks but operate independently. Each model loads the stacked GeoTIFF, applies nodata-aware normalisation, fits on training pixels, evaluates on test pixels, and writes a full-scene prediction GeoTIFF.

Dispatcher: src/model_runner.py :: ModelRunner.run_multiple_models()  →  delegates to individual demo files in hsmodel/
ModelDemo fileOutput TIF
Random Forest demo_RandomForests.py rf_final_prediction_map.tif
XGBoost demo_eXtremeGradientBoosting.py xgb_final_prediction_map.tif
S²Mamba demo_mambaStateSpaceModel.py MAMBA_final_prediction_map.tif
SpectralFormer demo_SpectralFormer.py VIT_final_prediction_map.tif

After all models complete, convert prediction maps to publication-quality PNG figures:

python -m preprocessing.export_figures --dataset RabshiPRISMA

Figures are saved in output/experiments_XXX/figures/ as individual 300 DPI PNGs with scale bar, north arrow, legend, and a 2×2 comparison panel.

◆ Orchestration Layer

The entry point for all pipeline execution is src/pipeline.py and src/model_runner.py, both instantiated by main.py.

# src/pipeline.py — simplified call graph
HyperspectralPipeline.run_preprocessing()
  ├── _step_convert_satellite_data()   # Step 1
  ├── _step_process_labels()           # Step 2
  ├── _step_apply_colormap()           # Step 3
  └── _step_create_masks()             # Step 4

ModelRunner.run_multiple_models([RF, XGB, MAMBA, VIT], all_classes)
  ├── run_random_forests()             # Step 5a
  ├── run_xgboost()                    # Step 5b
  ├── run_mamba()                      # Step 5c
  └── run_spectral_former()            # Step 5d
Config singleton: All pipeline classes import the module-level config object from projutils/config.py. When Config(satellite_name=...) is constructed, _create_required_dirs() automatically creates every intermediate and output directory listed in the config — no manual directory setup needed.
